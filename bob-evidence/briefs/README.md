# Task briefs

Workflow step 1: a human writes the requirement and the acceptance criteria
before any session starts.

`uc-03-callsheet-modernization.md` is the full brief for the primary use case,
and it is the pattern the others follow — requirement, starting condition,
constraints on the work, mechanically checkable acceptance criteria, explicit
out-of-scope, and a note on how the session should be run so its output can be
judged.

UC-01, UC-02 and UC-04 to UC-06 are specified in `../USE_CASES.md` with their
acceptance criteria. Each gets a full brief here when it is scheduled; writing
six full briefs for sessions nobody has booked would be documenting intent as
though it were work.

A brief is approved as a *brief*. Approving the technical **plan** Bob produces
from it is a separate step, and it is recorded in the session record, not here.
